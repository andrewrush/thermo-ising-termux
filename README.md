# thermo-ising-termux

Высокопроизводительный **симулятор спиновых моделей** для Termux на Android aarch64.

## Зачем это нужно обычному человеку?

Этот проект — не просто «калькулятор для физиков». Он отвечает на вопросы, которые интересуют каждого:

**1. Почему магнит теряет магнетизм при нагревании?**
> Магнит на холодильнике — это миллиарды микроскопических стрелочек (спинов), которые смотрят в одну сторону. Нагрейте магнит — стрелочки начинают трястись и разбегаться в разные стороны. При определённой температуре (точке Кюри) хаос побеждает порядок, и магнит «забывает», куда смотреть. Наш симулятор показывает этот момент в реальном времени — вы видите, как чёрные и серые пятна (магнитные домены) сливаются или распадаются на хаос.

**2. Почему вода закипает ровно при 100°C, а не постепенно?**
> Фазовые переходы — это не плавные изменения, а резкие скачки. Вода не становится «чуть-чуть газом» — она внезапно закипает. Точно так же магнит внезапно теряет силу. Наш код вычисляет эту «точку невозврата» для магнитной решётки — и вы видите на графике, как свойства материала обрываются, а не тянутся.

**3. Может ли телефон считать серьёзную науку?**
> Да. Ваш Android — это компьютер с 8 ядрами ARM64, аппаратным генератором случайных чисел и датчиками. Мы используем энтропию из чипа телефона (а не псевдослучайные числа) для запуска физических симуляций. Это значит: ваш телефон буквально «ощущает» тепловой шум своего же процессора и превращает его в научный эксперимент.

**4. Зачем измерять энергию батареи во время счёта?**
> Каждый шаг симуляции — это миллионы операций. Мы замеряем, сколько джоулей уходит на один шаг, и сравниваем модели. Это как «расход топлива» для алгоритмов. Обычный человек получает интуицию: «сложная задача = дорого для батареи».

**5. Что я увижу, запустив это?**
> ASCII-графику в терминале: чёрные квадраты █ и серые ░ — это мини-магниты. При низкой температуре они объединяются в огромные «континенты». При нагревании континенты распадаются на хаотичные островки. Это красиво, как лава-лампа, но за ней стоит нобелевская физика (Ларс Онсагер, 1944).

## Модели

| Модель | Файл | Размерность | Tc | Алгоритм |
|---|---|---|---|---|
| 2D Ising | `ising.c` | 2D | 2.269 | Metropolis |
| 2D Ising (Viz) | `ising_viz.c` | 2D | 2.269 | Metropolis + ASCII domains |
| 2D Ising (Wolff) | `wolff.c` | 2D | 2.269 | Wolff cluster |
| 3D Ising | `ising3d.c` | 3D | 4.51 | Metropolis |
| 3D Heisenberg | `heisenberg.c` | 3D | 1.44 | Metropolis (continuous spins) |
| 2D Ising (GPU) | `gpu_wrapper.c` | 2D | 2.269 | OpenCL checkerboard |

## Новое в v5.4

### 1. Энергометрика — Joules per sample
`benchmark_power.sh` измеряет потребление батареи до/во время/после симуляции через `termux-battery-status`.

### 2. ASCII-визуализация доменов
`ising_viz_app` + `ascii_viz.sh` — Unicode-блоки █/░ показывают рост магнитных доменов в реальном времени.

### 3. Горячий старт с физической энтропии
`hotstart.sh` — начальное состояние решётки сидится из `/dev/urandom` (SoC HWRNG).

## Сборка

```bash
make
```

## Запуск

```bash
# ASCII-визуализация (L=32, T=2.0, 500K шагов)
./ascii_viz.sh 32 2.0 500000

# Энергометрика
./benchmark_power.sh 64 5000000

# Горячий старт
./hotstart.sh

# 3D Ising
./ising3d_app 16 4.51 2000000

# Heisenberg
./heisenberg_app 16 1.44 2000000

# Полный бенчмарк
./benchmark.sh
```
